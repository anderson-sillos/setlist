# Setlist 1.0.0 — candidata 5 (`v1.0.0-rc.5`)

Estado: preparação. A versão do produto permanece `1.0.0`; `rc.5` identifica a
candidata e não altera a versão exibida pelo aplicativo. A tag será criada após
a integração da PR e apontará para o commit usado nos builds.

## Correções desta candidata

- A abertura de Nova música não fica mais vazia quando a atualização de tela
  encontra uma consulta de música desativada. Erros de leitura de uma música
  existente continuam apresentados na edição.
- As sugestões de artista vêm do repertório da banda atual, incluem músicas
  arquivadas e não misturam dados de outras bandas.
- As sugestões do autocomplete aparecem em ordem alfabética. Selecionar uma
  opção fecha a lista; entrar novamente no campo ou editar o texto a exibe.
- No formulário Novo show, a rolagem ajusta a posição das sugestões de local
  para mantê-las visíveis com o teclado aberto.
- O componente de aviso de ações da versão de demonstração foi renomeado para
  `ActionNotice`.

## Builds e validação

Ainda não iniciados. Após a integração da PR, criar a tag imutável
`v1.0.0-rc.5` no commit candidato e gerar do mesmo checkout limpo:

- Android AAB pelo perfil `production-android`.
- iOS IPA pelo perfil `production`.
- Android APK para validação pelo perfil `production-android-validation`.
- Exportação Web com a configuração de produção e metadados da tag/commit.

Registrar os IDs EAS, contadores nativos, commit e evidências de validação nesta
nota e no manifesto da Release somente depois de conferir os artefatos. A
validação dos fluxos críticos Android, iOS e Web e o estado dos canais das lojas
permanecem pendentes.
